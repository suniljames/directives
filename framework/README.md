# Framework

Cross-team rules for how agents think, verify, and coordinate. **The boundary:** `framework/` applies to every team and every domain; [`teams/<team>/process/`](../teams/README.md) is one team's specific procedure. If a rule would be true for a sales team too, it belongs here.

| Read this… | When |
|---|---|
| [Reasoning](reasoning-framework.md) | You want the core work loop every agent follows (understand → plan → execute → verify). |
| [Verification](verification.md) | You need to know a change *actually* works — force-red discipline, independent instruments. |
| [Controls & Detectors](controls-and-detectors.md) | You're building anything that watches, blocks, or alerts — and must prove it can fire. |
| [Diagnosis](diagnosis.md) | Something is broken and the cause isn't proven yet. |
| [Agent Architecture](agent-architecture.md) | You're setting up builder/validator roles, session specialists, or cross-agent protocols. |
| [Orchestration](orchestration.md) | You're building or configuring a tool that routes work between agents. |
| [Fan-Out Safety](fan-out-safety.md) | You're spawning parallel sub-agents. |
| [Prompt Quality](prompt-quality.md) | You're writing files the agent process itself runs on (commands, agent definitions, configs). |
| [Safety](safety.md) | Always in force — the never-do rules. |
| [Data Safety](data-safety.md) | You're designing a path that deletes, rewrites, or disables protection on data. |
