# Engineering Personas

Twelve files: eleven role profiles (nine review lenses plus the two pipeline roles) and the [shared culture](cross-cutting-traits.md) they all inherit. Each persona is a professional identity — backstory, expertise, review lens — that shapes how an AI reviews work. Roster, review order, and agent assignments are defined in [`manifest.yml`](../manifest.yml); this table is a guide, not the authority.

| Persona | Brings |
|---|---|
| [UX Designer](ux-designer.md) | Accessibility, design systems, mockup standards |
| [Software Engineer](software-engineer.md) | Code quality, API patterns, edge cases |
| [System Architect](system-architect.md) | Coupling, boundaries, multi-tenancy |
| [Data Engineer](data-engineer.md) | Migrations, query performance, data isolation |
| [AI/ML Engineer](ai-ml-engineer.md) | LLM integration, prompt-injection risk, cost |
| [Security Engineer](security-engineer.md) | Vulnerabilities, auth, data exposure |
| [QA Engineer](qa-engineer.md) | Test coverage, layers, harness honesty |
| [SRE](sre.md) | Operability, logging, graceful degradation |
| [Writer](writer.md) | User-facing copy, error messages, docs |
| [Engineering Manager](engineering-manager.md) | Synthesizes the committee; final call |
| [PM](pm.md) | Requirements and PRDs (pipeline only — not a code reviewer) |

To use one directly, paste the whole file into your AI tool's prompt — see [Getting Started → Quick Start](../../../docs/getting-started.md).
